# DataPilotAgent MVP 技术方案设计（修订版）



## 1. 总体架构

- **前端**：Vite8+ React 18 + TypeScript + shadcn/ui (Base UI) + Tailwind CSS V4 + recharts（shadcn/ui Chart 封装）+ Monaco Editor + Zustand
- **后端**：FastAPI + SQLAlchemy 2.0 (async) + Pydantic v2 + PostgreSQL 16 + Redis 7
- **AI**：双协议适配（OpenAI / Anthropic），统一抽象
- **任务队列**：PostgreSQL `FOR UPDATE SKIP LOCKED`，任务状态与执行事务分离
- **流式通信**：SSE（fetch + ReadableStream）
- **部署**：Docker Compose（仅应用层：backend、frontend 构建、Nginx）；PostgreSQL / Redis / MinIO 使用远程实例
- **附件存储**：远程 MinIO 对象存储（生命周期由应用按会话/过期策略管理）

环境已备好：见根目录 `.env` 可以直接用（远程 PostgreSQL、Redis、MinIO 连接信息）

**开发契约**：Block 内容结构、SSE 事件载荷、LLM 结构化输出协议、附件执行引擎详见 **docs/Block与协议规范.md**

### 2.2 数据库表结构

所有表使用 UUID 主键，时间字段使用 `timestamptz`。

```sql
-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 会话表
CREATE TABLE sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(255) DEFAULT '新会话',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 消息表
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    role VARCHAR(20) NOT NULL,           -- user / assistant / system
    blocks JSONB NOT NULL DEFAULT '[]',  -- Block 数组
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 数据源表
CREATE TABLE datasources (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,
    type VARCHAR(20) NOT NULL,           -- postgresql / mysql / sqlite / csv / excel / json
    config JSONB NOT NULL DEFAULT '{}',  -- 连接配置（密码等敏感字段加密存储）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 附件表
CREATE TABLE attachments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    file_name VARCHAR(255) NOT NULL,
    object_key VARCHAR(500) NOT NULL,    -- MinIO 对象键 attachments/{session_id}/{attachment_id}/{file_name}
    file_type VARCHAR(20) NOT NULL,      -- csv / excel / json
    parsed_schema JSONB,                 -- 解析后的 schema（列名/类型/行数/sheet 名）
    expires_at TIMESTAMPTZ NOT NULL,     -- 过期时间（7天后）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 任务表
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES sessions(id) ON DELETE SET NULL,
    type VARCHAR(50) NOT NULL,           -- query / analysis / complex_analysis / file_parse
    status VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending/running/success/failed/cancelled
    params JSONB NOT NULL DEFAULT '{}',
    result JSONB,
    error TEXT,
    progress INTEGER DEFAULT 0,
    current_step VARCHAR(255),
    retry_count INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    started_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ
);

-- 配置表
CREATE TABLE configs (
    key VARCHAR(100) PRIMARY KEY,
    value JSONB NOT NULL,
    category VARCHAR(50) NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- LLM 供应商表（多实例、全局共享；运行时默认取 is_default 行，空表回退 configs 的 llm.* 键）
CREATE TABLE llm_providers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL,
    type VARCHAR(20) NOT NULL,               -- openai / anthropic
    base_url VARCHAR(500) NOT NULL DEFAULT '',
    api_key VARCHAR(1000) NOT NULL DEFAULT '', -- Fernet 加密存储（enc: 前缀），出参恒掩码 ******
    models JSONB NOT NULL DEFAULT '[]',      -- 可用模型列表
    default_model VARCHAR(100) NOT NULL DEFAULT '',
    is_default BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 反馈表
CREATE TABLE feedbacks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    message_id UUID NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
    rating SMALLINT NOT NULL,            -- 1 / -1
    comment TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 模板表（可复用分析配置）
CREATE TABLE templates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    datasource_id UUID REFERENCES datasources(id) ON DELETE SET NULL,
    sql_text TEXT,
    chart_config JSONB,                  -- 图表类型与配置
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 日志表（统一存储）
CREATE TABLE logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    timestamp TIMESTAMPTZ NOT NULL DEFAULT now(),
    level VARCHAR(10) NOT NULL,          -- DEBUG/INFO/WARNING/ERROR/CRITICAL
    category VARCHAR(50) NOT NULL,       -- system/application/ai/error/audit
    message TEXT NOT NULL,
    context JSONB DEFAULT '{}',          -- 结构化附加信息
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

索引：
- `messages(session_id, created_at)`
- `tasks(status, created_at)`
- `logs(timestamp, category, level)`

### 2.3 API 设计（仅 GET / POST，统一路径约定）

所有接口返回统一格式：`{ "code": 0, "data": ..., "message": "ok" }`，错误码非 0。流式接口返回 SSE。

**路径约定**：
- 查询列表：`GET /api/resource`
- 创建：`POST /api/resource`
- 更新：`POST /api/resource/update`（body 含 id）
- 删除：`POST /api/resource/delete`（body 含 id）
- 其他操作：`POST /api/resource/action`

#### 认证
- `POST /api/auth/login` — 登录，返回 JWT（限流：每 IP 每分钟 5 次）
- `GET /api/auth/me` — 获取当前用户信息
- `POST /api/auth/change-password` — 修改密码（默认账号首次登录后提示修改）

#### 会话
- `GET /api/sessions` — 获取会话列表（支持搜索、分页）
- `POST /api/sessions` — 创建新会话
- `POST /api/sessions/update` — 重命名（body: {id, title}）
- `POST /api/sessions/delete` — 删除（body: {id}）
- `GET /api/sessions/{id}/messages` — 获取会话消息

#### 对话（核心）
- `POST /api/chat/stream` — 发起对话，SSE 流式返回
  - 请求体：`{ session_id, message, attachments?: [], datasource_id?, action_block_id? }`
  - SSE 事件类型：`token`、`block_start`、`block_update`、`block_end`、`task_status`、`error`、`done`
- `POST /api/chat/execute` — 执行用户编辑后的 SQL 或确认操作（返回任务 ID 或直接执行）
- `POST /api/chat/feedback` — 提交反馈

#### 数据源
- `GET /api/datasources` — 列表（敏感字段脱敏）
- `POST /api/datasources` — 创建
- `POST /api/datasources/test` — 测试连接
- `POST /api/datasources/update` — 更新
- `POST /api/datasources/delete` — 删除
- `GET /api/datasources/{id}/preview` — 预览数据

#### 附件上传
- `POST /api/upload` — 上传文件（multipart/form-data），创建解析任务并返回附件 ID
- `GET /api/upload/{id}/status` — 获取解析状态（从任务状态获取）

#### 导出
- `POST /api/export` — 导出数据/图表/对话
  - 请求体：`{ type: "table"|"chart"|"conversation", format: "csv"|"excel"|"json"|"png"|"svg"|"pdf"|"markdown", data: {...} }`

#### 任务
- `GET /api/tasks/{id}` — 获取任务状态
- `POST /api/tasks/{id}/cancel` — 取消任务
- `GET /api/tasks/{id}/stream` — SSE 订阅任务进度（点对点频道）

#### 模板
- `GET /api/templates` — 模板列表
- `POST /api/templates` — 创建模板
- `POST /api/templates/update` — 更新（body 含 id）
- `POST /api/templates/delete` — 删除（body 含 id）

#### 配置
- `GET /api/config` — 获取所有配置（敏感值脱敏）
- `POST /api/config/update` — 更新配置（支持批量）
- `POST /api/config/test` — 测试 LLM 配置

#### LLM 供应商
- `GET /api/llm/providers` — 列表（默认优先；`api_key` 恒掩码 `******`）
- `POST /api/llm/providers` — 新增（首个自动设为默认）
  - 请求体：`{ name, type, base_url?, api_key?, models?, default_model? }`
- `POST /api/llm/providers/update` — 更新（body 含 id；`api_key` 掩码/空串 = 保留旧密文）
- `POST /api/llm/providers/delete` — 删除（body 含 id；删除默认后自动提升最新一个为默认）
- `POST /api/llm/providers/{id}/set-default` — 设为默认供应商
- `POST /api/llm/providers/{id}/test` — 连通测试 → `{ ok, model?, latency_ms?, error? }`

#### 日志
- `GET /api/logs` — 查询日志（支持分类、级别、时间范围、分页）
- `POST /api/logs/export` — 导出日志 CSV

### 2.4 任务队列实现（PostgreSQL）

**事务边界修正**：

- Worker 循环：
  1. 开启一个事务，使用 `SELECT ... FOR UPDATE SKIP LOCKED` 锁定一个 `status='pending'` 的任务，更新其状态为 `running`，记录 `started_at`，提交事务。
  2. 在事务外执行任务逻辑。
  3. 执行成功后更新 `status='success'`，`completed_at`，`result`。
  4. 执行失败更新 `status='failed'`，`error`。
  5. 若被取消，更新为 `cancelled`。
- **超时恢复**：后台定时任务（每分钟）将 `running` 且 `started_at` 早于当前时间减去超时阈值的任务标记：
  - 查询类：`failed`（可重试）
  - 写操作类：`failed` 并提示人工检查。
- **任务重试**：前端重试按钮触发创建新任务（复制原参数），或直接更新原任务为 `pending`（重置状态）。

**附件解析纳入任务队列**：

- 上传文件后，创建 `tasks` 记录，`type='file_parse'`，`params` 包含 `attachment_id`。
- Worker 消费该任务，执行文件解析（pandas/openpyxl），更新 `attachments.parsed_schema`，并更新任务状态。
- 前端附件状态从任务状态获取，重试即创建新任务。

**任务取消机制**：
- 更新任务状态为 `cancelled`，并在执行函数中定期检查状态，若已取消则终止执行。

### 2.5 LLM 双协议适配

定义统一抽象类 `BaseLLMProvider`：

```python
class BaseLLMProvider(ABC):
    @abstractmethod
    async def stream_chat(self, messages, **kwargs) -> AsyncGenerator[str, None]: ...
    @abstractmethod
    async def chat(self, messages, **kwargs) -> str: ...
    @abstractmethod
    async def generate_sql(self, question, schema, history) -> str: ...
    @abstractmethod
    async def generate_python(self, question, data_info, history) -> str: ...
    @abstractmethod
    async def analyze_intent(self, question, context) -> dict: ...
```

**OpenAIAdapter**：使用 `openai` SDK，流式处理 `chunk.choices[0].delta.content`。

**AnthropicAdapter**：使用 `anthropic` SDK，消息格式转换（system 字段提取），流式处理 `content_block_delta` 事件。

**Provider 工厂**：根据配置动态创建适配器，并缓存实例（配置变更时重建）。

**结构化输出统一抽象（tool calling）**：

Agent 与 LLM 的结构化交互统一走 tool calling，`BaseLLMProvider` 补充两个方法：

- `chat_with_tools(messages, tools, **kwargs) -> {content, tool_calls}`：非流式工具调用
- `stream_chat_with_tools(messages, tools, **kwargs)`：流式版本，文本部分逐 token 推送，工具调用参数整体返回

OpenAI 协议使用 `tools` / `tool_choice` 参数；Anthropic 协议使用 `tools` + `tool_use` content block。两个适配器将各自格式归一为内部 `ToolCall(name, arguments)` 结构，上层 Agent 无感知。不支持 tool calling 的模型自动降级为严格 JSON 模式（JSON Schema 提示词 + 解析失败重试 1 次）。

Agent 工具集定义（意图识别、SQL 生成、图表配置等）及各工具与 Block 的映射关系见《Block与协议规范》。

### 2.6 配置热更新

- 配置存储在 `configs` 表，Redis 缓存哈希 `config:all`。
- 读取：`ConfigService.get(key)` → 先查 Redis，未命中查 DB 并写入 Redis。
- 更新：`ConfigService.set(key, value)` → 更新 DB → 删除 Redis 对应 key → 发布 Pub/Sub 消息 `config_changed`。
- 各服务节点订阅 `config_changed`，收到后清空本地配置缓存。
- 进行中的会话在开始时加载配置快照，中途不改变。

### 2.7 日志管理

- 使用 `structlog` 输出结构化日志，同时将日志写入 PostgreSQL（异步批量）。
- `LogService` 使用 `logging.handlers.QueueHandler` + 单独线程同步写入数据库，避免进程退出丢失。
- 日志分类：`system`、`application`、`ai`、`error`、`audit`。
- 管理后台通过 `GET /api/logs` 查询，支持过滤和分页。

### 2.8 安全

- JWT 认证：`python-jose`，HS256，有效期 24h。
- 密码哈希：`bcrypt`。
- **独立加密密钥**：新增环境变量 `ENCRYPTION_KEY`（Fernet 密钥，44 字节 base64），与 `SECRET_KEY` 分离。数据源密码、API Key 等敏感字段使用 `Fernet(ENCRYPTION_KEY)` 加密后存储。如果 `ENCRYPTION_KEY` 未设置，启动时自动生成并存储在持久化卷中。
- **数据源密码脱敏**：API 返回数据源列表时，对 `config` 中的密码字段替换为 `******`。更新数据源时，若前端传回的密码为脱敏值，则保留原密码；若为新值，则加密存储。
- SQL 安全：在 `SQLAgent` 中解析 SQL 类型，根据配置的黑白名单决定拦截或确认。
- 文件上传：校验扩展名（csv/xlsx/xls/json）、MIME、大小限制（默认 20MB）。
- **Python 沙箱简化**：使用 `RestrictedPython` 编译 + `subprocess` 子进程执行，设置 `resource.setrlimit` 限制 CPU 时间（10s）、内存（256MB）。仅允许导入白名单模块：`pandas`, `numpy`, `scipy.stats`, `datetime`, `json`, `math`。超时使用 `subprocess.run(timeout=30)`。
- API 限流：使用 Redis 固定窗口限流，普通接口每个用户每分钟 10 次，登录接口每 IP 每分钟 5 次。

## 4. 关键实现细节

### 4.1 对话流程

1. 前端 `POST /api/chat/stream`（session_id, message, attachments, datasource_id）
2. 后端保存用户消息到数据库。
3. `ChatService.process_message`：
   - 加载上下文（历史消息、数据源 schema、附件 schema）
   - 调用 `analyze_intent` 识别意图
   - 调用相应 Agent 执行，逐步生成 Block 并通过 SSE 推送
4. 后端保存 assistant 消息和 Block 数组。
5. 前端接收 SSE 事件更新 UI。

### 4.2 SSE 事件设计

| 事件类型 | 数据 | 说明 |
|---------|------|------|
| `token` | `{ content: string }` | 文本 token |
| `block_start` | `{ block_id, block_type }` | 开始一个 Block |
| `block_update` | `{ block_id, data }` | 更新 Block 内容 |
| `block_end` | `{ block_id }` | Block 完成 |
| `task_status` | `{ task_id, status, progress }` | 任务状态更新 |
| `error` | `{ message }` | 错误 |
| `done` | `{ message_id }` | 整条消息完成 |

### 4.3 附件处理

- 上传文件：流式写入远程 MinIO（对象键 `attachments/{session_id}/{attachment_id}/{file_name}`），创建 `attachments` 记录，创建 `file_parse` 任务。
- Worker 执行解析：从 MinIO 拉取文件流，CSV 使用 pandas，Excel 使用 openpyxl（默认第一个 sheet，sheet 名写入 parsed_schema），JSON 加载。
- 解析后将数据导入**会话级临时 SQLite 数据库**（`data/tmp/{session_id}.db`，表名 `att_{attachment_id}`），并更新 `attachments.parsed_schema`（列名、推断类型、行数、sheet 名）。
- 附件临时表 schema 合并到对话上下文，NL2SQL 生成的 SQL 可直接查询 `att_*` 表。
- **跨引擎 JOIN**：主数据源（PG / MySQL）与附件临时表（SQLite）不在同一引擎，MVP 不支持直接 JOIN。AI 检测到跨源 JOIN 时拆为两步：分别查询后在 Python Agent 中用 pandas merge 合并。
- 会话删除或附件过期（7 天）时：删除 MinIO 对象、删除临时 SQLite 表、删除记录。

### 4.4 SQL 安全判定

- 使用 `sqlparse` 提取操作类型。
- 根据配置：
  - 禁止操作（如 DROP DATABASE）：直接拦截，返回错误 Block。
  - 危险操作（DROP/ALTER/TRUNCATE/大规模UPDATE/DELETE）：返回 confirmation Block。
  - 安全操作：直接执行。
- 查询结果行数超过 `MAX_QUERY_ROWS` 时截断。

### 4.5 任务并发

- 启动 N 个 worker 协程（默认 3）。
- 每个 worker 独立从任务表获取任务，避免锁竞争。
- 任务执行中使用 `asyncio.shield` 防止取消导致状态不一致。

### 4.6 默认配置初始化

- 在 Alembic 迁移后或应用启动时执行初始化脚本（如 `python -m app.initial_data`）。
- 检查 `configs` 表是否为空，若为空则插入默认配置项（与 PRD 一致）。
- 检查 `users` 表是否为空，若为空则创建默认管理员（用户名 `admin`，初始密码 `Admin@12345`，bcrypt 哈希）。
- 检查 MinIO bucket（默认 `datapilot`）是否存在，不存在则创建。
- 默认配置项包括：LLM 参数、系统行为参数、日志保留天数等。

### 4.7 导出 PDF 实现

- 图表导出 PDF：使用 `jsPDF` + recharts 渲染出的 SVG（序列化 DOM SVG → Image → canvas → dataURL）前端生成，无需服务端。
- 对话记录导出：MVP 支持 Markdown 导出（文本、表格转 Markdown 表格、图表以图片 base64 嵌入）。PDF 导出通过浏览器打印实现（提示用户另存为 PDF）。

## 5. 部署

### 5.1 Docker Compose 配置

```yaml
version: '3.8'
services:
  backend:
    build: ./backend
    env_file: .env                # 复用根目录 .env（远程 PostgreSQL / Redis / MinIO）
    environment:
      DATABASE_URL: postgresql+asyncpg://${PG_USER}:${PG_PASSWORD}@${PG_HOST}:${PG_PORT}/${PG_DB}
      REDIS_URL: redis://:${REDIS_PASSWORD}@${REDIS_HOST}:${REDIS_PORT}/0
      SECRET_KEY: change-me
      ENABLE_AUTH: "true"
      OPENAI_API_KEY: ""
      ANTHROPIC_API_KEY: ""
    # PostgreSQL / Redis / MinIO 均为远程实例，无本地依赖
  frontend:
    build: ./frontend
    # 构建后由 Nginx 服务静态文件，不运行 dev server
    volumes:
      - frontend_build:/app/dist
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - frontend_build:/usr/share/nginx/html:ro
    depends_on:
      - frontend
      - backend
volumes:
  frontend_build:
```

**ENCRYPTION_KEY 说明**：生产部署必须通过环境变量显式设置并妥善保管（密钥丢失将导致已加密的数据源密码、API Key 无法解密）；开发模式未设置时自动生成并持久化到 `./data/encryption_key`。

### 5.2 Nginx 配置

```
server {
    listen 80;

    location /api/ {

    }
```

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| LLM 输出不稳定 | 使用 JSON 模式或严格提示词，失败重试 |
| 任务恢复导致重复执行 | 查询类可重试，写操作人工确认 |
| 日志量过大 | 异步批量写入，定期清理 |
| SSE 连接中断 | 自动重连，状态恢复 |
| Python 沙箱逃逸 | RestrictedPython + 资源限制，最小权限 |
| 加密密钥丢失 | 生产环境显式配置 ENCRYPTION_KEY 并备份；开发环境自动生成并持久化 |
| 远程 MinIO / PostgreSQL / Redis 不可用 | 上传与解析任务失败可重试，错误信息明确提示；客户端连接超时统一 10s |
| 前端构建体积过大 | 代码分割，按需加载 Monaco Editor |
